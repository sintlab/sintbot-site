每个版本改了什么

SintBot 从 1.4.1 到 1.4.32 的每个版本，新版在前，内容与该版发布的更新说明一致。

最新版本 1.4.32 ↓

2026-11-21

1.4.32 · 新群默认放开、等待更短

新绑定的群默认完全访问、数据明文
在控制台添加群项目或通过接入页接入新群时，执行模式默认是「完全访问」，数据输出默认是明文（手机号和邮箱原样显示）。已绑定的群不变；要收紧，在「群 · 项目」卡里改回只读或白名单、数据输出改回遮盖。
回执等待默认 3 秒
收到消息后 3 秒内还没有任何输出，就先回一张「已收到，正在处理」卡片（原来是 25 秒）。在通用设置里可改，填 0 不发。
单轮超时默认 60 分钟
一轮任务的默认上限从 30 分钟改为 60 分钟。已在配置里填过的值不变。
模型库不再预置 DeepSeek 卡片
模型页只显示已配置的模型卡。DeepSeek 仍在「添加模型」的预设里。
添加 Claude 订阅登录时不再显示型号输入框
选「Claude 订阅登录」预设时，型号输入框和端点、Key 一起隐藏；型号按群在「群 · 项目」里选。

2026-11-20

1.4.31 · 控制台更清爽

添加群项目、添加模型：按钮更安静
群 · 项目页和模型页右上角的按钮改成带加号的细边框样式，名字改为「添加群项目」「添加模型」。在弹窗里选中已绑定的群时，标题会变成「修改群项目」。
列表为空时有添加卡
还没有群项目或模型时，列表位置显示一张虚线添加卡，点一下就打开对应的弹窗。
点版本号打开软件更新
点击左上角的版本号，直接跳到「设置 → 软件更新」卡。
设置合并为一张「通用设置」卡
界面语言、机器人与网络、运行限制和访问地址合进一张「通用设置」卡，默认折叠，折叠时显示语言、并发上限、是否设了代理和访问范围；原来单独的「界面」卡去掉。

2026-11-20

1.4.30 · 少挂群、型号按群选、控制台整理

执行器没开工就报错，不再挂群
Claude Code，或关掉了「后续消息加入当前处理」的 Codex 群，还没开始处理就明确报错时（如额度用完、登录失效、上次的会话接不上、所选型号用不了、暂时连不上模型服务），这条消息按「没有处理」收尾：群里说明原因、请你之后重发，群照常处理后续消息。此前这种情况会挂起整个群，之后的消息只回「上一个任务结果不明」，看不出原因。会话接不上时，下一条从新会话开始；Codex 开工前失败时，服务日志会写明它输出了什么（已打码）。例外：升级切换后 90 秒内（这时还可能回退到旧版），或这一轮合并了多条消息时，仍按旧规则挂群。开着「后续消息加入当前处理」的 Codex 群（默认开着）这一版仍按旧规则处理。
服务崩溃打断的消息：告知，不重做，不挂群
服务因没接住的错误退出后，重启时被打断的那条消息会在原会话收到一条「刚才这条没做完」的说明（带提问人和原文开头），不会自动重做，群也不再挂起。会话保留，下一轮会提醒模型不要自行接着做那条，除非你再次要求。仍挂群的情形：这一轮合并了多条消息、会话里还有排队的消息、执行器还没确认开工或最终回复已开始发送，以及手动停止服务、升级重启时打断的那一轮。
封存挂起的群，不再被它自己拦住
在控制台「需要你处理」里封存一个挂起的群时，这个群自己卡住的那一轮不再算作「其他群还有任务」，可以直接封存；其他群正在处理或有排队时仍要等它们结束。此前额度用完卡住的群可能因此被拒，只能停服务后用命令行封存。
控制台整理
设置页的飞书、企业微信、Slack 三张平台卡默认收起成一行（图标、名字、状态点和摘要），点开看详情，连接出错时状态点变红。界面语言从侧栏移到设置页顶部新的「界面」卡。控制台不再内置版本历史：软件更新卡底部的「更新记录 →」、品牌旁的版本号和群里的升级公告，都链到官网更新记录里对应版本那一节。英文界面里残留的中文改成了英文。
型号按群选，添加模型先填 Key
用 API Key 接入的模型卡也和订阅卡一样，在「群 · 项目」的群卡上或用 /model 按群选型号；卡填了 Key 后，下拉里列出这家当前可用的型号，没选过的群用卡上存的型号。「添加模型」改为选好预设后先填 API Key，可点「验证 Key」当场试跑一轮，没通过会说明原因（如 Key 被拒、端点不是 Anthropic 格式）；端点、小模型、默认思考深度等收进「高级」。自定义端点仍在卡上填端点和型号，各群共用。
模型预设调整
预设列表调整：GLM 预设升到 glm-5.3，新增 Kimi，去掉火山方舟；DeepSeek、MiniMax 预设的默认型号也按官方文档更新。MiniMax 预设改用官方当前端点 api.minimax.cn。模型卡和预设显示服务商的小标识，Claude 订阅与 GPT via Codex 两张订阅预设排在最前，终端向导里的可选厂商同步调整。已有的模型卡（包括火山方舟卡和旧 MiniMax 端点的卡）不受影响，照常使用和编辑。
Claude Code 版本检测与升级
控制台的 Claude 订阅模型卡显示本机 Claude Code 程序的版本，有新版时确认后可一键升级：用 npm 装的用 npm 重装，用官方安装器装的走它自带的更新，其他方式装的提示到机器上手动升级。有群正在用 Claude Code 处理任务或排队时不会升级，每次尝试都记入审计日志；用 Claude Code 的群从下一轮起用新版。
安装完成提示改为 Slack 优先
一行安装命令装完后，提示先给出在 Slack 里接入项目的指南链接，再说明飞书和企业微信同样支持，并附各自的链接。

2026-11-19

1.4.29 · 定时任务、崩溃时先收尾再退出

定时任务
在控制台群卡「更多设置 → 定时任务」里新建、编辑、暂停和删除。任务有三种：交给模型（到点先在会话里发一行「【定时】」消息，随后按一条普通消息处理）、只发一句话、在项目目录里运行一条命令（不经模型，失败或超时时发一行提示）。时间可写 cron、@daily 这类别名、「每天 09:00」或一次性的日期时间，可按任务指定时区。每次到点至多触发一次；服务没在运行或晚了两分钟以上的不补；失败和结果不明的都不重试。这一版任务只能在控制台建和改，企业微信会话暂不支持。
崩溃时先收尾再退出
服务遇到没接住的错误时，先在日志里记下时间和调用栈，停掉定时任务和正在运行的执行器、释放锁、清理临时文件，再以退出码 1 退出，由系统重新拉起；收尾最多等 20 秒。此前会当场退出，Codex 或 Claude Code 子进程可能留在后台继续运行。被打断的那一轮在重启后仍按结果不明处理。
代理地址校验更严
Slack 接入和设置里的代理地址，主机必须写 IP 地址或英文（纯 ASCII）主机名：中文域名、xn-- 开头的域名标签、全角的点和数字都不再接受；方括号里的 IPv6 地址按标准规则检查。之前这些写法有的能保存，到连接时才报别的错。
Slack 与控制台小修
Slack 里封存记录核对失败时，挂起会话的 ⚠️ 不再跟着漏挂，失败会写进服务日志；同一个 Slack 应用被另一台机器连着时，日志说法更准确。控制台英文界面里「后续消息加入当前处理」开关有了英文。

1.4.28 · Slack 说英文、线程里停止，排满不再挂群

排满时提示重发，不再挂起群
排队已满（已有 2 条在等）时，再来的消息不处理，机器人提示等当前任务结束后重发，正在运行的任务不受影响。此前在飞书、企业微信和私聊里，这种情况会中断当前任务并挂起整个群。当前任务正在收尾时到达的消息，也改为提示稍后重发。
Slack 里默认说英文
机器人在 Slack 里的提示、命令回复、状态和报错改为英文，并请模型用英文回答（成员用别的语言提问时仍跟随提问的人）。已接入的 Slack 会话升级后同样变为英文；要中文，在控制台 Slack 群卡「更多设置 → 群内提示语言」里改。飞书、企业微信和本机对话不变。
Slack 频道里各线程分开处理
任务进行中在频道里另起的 @ 不再并进当前任务，而是单独排队、单独处理，答案回到各自的线程；只有同一线程里的补充才会并进正在运行的任务。在线程里回复 !stop 只停这个线程的任务，排队的照常处理；在频道里另起一条 @机器人 !stop 或用 /sint stop，仍停止当前任务并清空排队。
Slack 里没完成的消息会标出来
服务被强行停止或会话被封存后，没完成的消息打上 ⚠️，并提示需要的话重新发送，这句提示只发一次。删除带回复的排队消息现在也能取消；更换连接时的几处问题已修复。
Slack 接入：代理、Agent 选项与提示
接入页的 Slack 步骤会预填检测到的终端代理（只支持 http），它作为整个服务的网络代理保存，其他平台和本机的模型工具也会走它。「声明为 Slack Agent」改为可选，默认不勾。机器人不在频道里时提示先用 /invite 请它进来；同一个 Slack 应用被另一台机器连着时，控制台会提示。
私聊、单聊的说法
Slack 私聊里称「这个私聊」、频道里称「本频道」，企业微信单聊里称「这个单聊」，帮助、状态和提示都按会话类型说；企业微信单聊的项目说明不再写「在群里 @ 机器人」。
控制台小修
升级 Codex 失败后按钮会恢复，并保留失败原因（本机路径打码）；模型卡另外指定了 Codex 程序、与系统里的不是同一个时，改为提示手动升级。同时运行的任务数按 1–32 校验，服务运行中修改会说明要改配置文件并重启。

1.4.26 · 控制台升级 Codex、配置历史与稳定性

控制台里升级 Codex、刷新型号
模型卡验证登录成功后重新读取可选型号，写明新增和不再提供的型号；群里 /model 先等新清单（最多 8 秒）。Codex 模型卡显示本机 Codex 程序的版本，有新版且是 npm 全局安装时可一键升级；有群正在用 Codex 处理任务时不会升级。
配置历史与还原
服务启动和每次在控制台改设置后自动存一份配置（保留最近 50 份）。sintbot config history 列出每份改了哪些设置，不显示值；sintbot config restore <版本> 在服务停止时把配置还原成那一份。
更稳
格式异常的请求地址不再让服务退出；飞书接口请求 30 秒没有响应就放弃，不再占住群；预览按文件的实际位置判断能否访问；排队的消息开始时读取群的最新设置；控制台只接受合理范围内的并发数和单轮时长；免密访问只给不经反向代理的本机请求。
空闲整理后接得上上一条回复（实验性）
Claude Code 空闲时整理完上下文，下一轮会带上上一轮已经发出的回复原文，群里按编号说「1 和 3」也能接上。只在内存里保留，服务重启后不带。

1.4.25 · 控制台更清爽

群项目卡片只留能用的
卡片只显示这一版可用的设置：模型、思考深度、执行模式、忙时跟进、数据输出和插件（插件这一版只能查看）。暂未接入的预览、定时任务、仓库、设计风格、图标、画布和解除绑定不再出现；Claude 的白名单收成一行，点开再编辑。

概览默认不选群
打开概览时不再预先选中群项目，点了哪个群才显示它的任务活动，再点一次收起。

1.4.24 · 接入 Slack

在 Slack 里用 SintBot
私聊机器人直接发任务，频道里 @它；答案回在私聊里或你那条消息的线程里。通过 Socket Mode 连接，不需要公网地址，免费工作区也能用。
三步接入，不用开终端
接入页和控制台设置里选 Slack：用已经填好的链接创建你自己的应用，粘贴两枚令牌，再给机器人发一句话就绑定项目。贴错令牌会直接指出贴的是哪一种。
看得见在不在跑
任务进行中，你的消息上有 ⏳，频道线程里有 Stop 按钮；答案送达后 ⏳ 变成 ✅。任务进行中补发的消息被读到后也会挂上 ⏳。
命令以 ! 开头
Slack 把 / 留给它自己的命令，所以用 !status、!stop、!skip、!new、!model；线程之外也可以用 /sint stop。随任务发来的图片和文件会保存到本机交给任务。
控制台直接建飞书群
「群 · 项目 → 配置群项目」里可以创建新的飞书群并选中绑定，不用先去飞书里建群。

1.4.22 · 扫码接入企业微信

扫码创建企业微信机器人
首次接入页选择企业微信，或在控制台设置里添加，用手机企业微信扫码即可创建机器人，凭据自动保存在这台 Mac；已有机器人也可以手动填写 Bot ID 和 Secret。

2026-11-13

1.4.21 · GPT 群可以开 Fast，暂停的群在控制台处理

GPT 群可以单独开 Fast
Codex 模型多了「速度」选项：标准或 Fast。控制台群卡、群里发 /model fast（回到标准发 /model 标准）、/model 弹出的模型卡上都能开；只改速度不重置会话，任务进行中也能改，下一条消息生效。默认不开；按群、按模型卡分开记；定时任务始终按标准速度。所选型号没有 Fast 档时不让开，换成没有 Fast 档的型号会自动回到标准并说一句。开 Fast 的回执写明代价：约 1.5–2 倍速，额度按 2.5 倍扣。
没开 Fast 时明确按标准速度跑
每轮明确请求标准速度，只有群中主动开启 Fast 时才请求加速，避免继承执行器的默认加速配置。App Server 明确回报回退时，卡片页脚不再显示 Fast；旧执行器和 exec 路线未回报实际档位时不能证明加速已生效。
暂停的群在控制台里封存并继续
任务进行中服务被强杀（断电、强制重启）后，所有群都暂停时服务照常启动，控制台可用；概览页「需要处理」卡和本机对话页提供「封存并继续」：原记录原样存档，那条消息不再处理，服务自动重启后用新的记录继续。只在后台托管运行时提供；前台运行仍按使用指南在终端处理。
后台服务被停用时不再升级
后台任务在系统里被停用（例如登录项里关掉）时，控制台升级会先拒绝并提示，避免升级后服务起不来。
DeepSeek 预设
预设 DeepSeek Flash，API Key 自行填写；型号与思考深度按群配置。
缺密钥提前提示
第三方模型缺少 API Key 时不启动执行器；未填密钥的模型卡仍可在群项目中选择。

群里新增 /skip

1.4.1 · 一个群出问题，只停这个群

一个群出问题，其他群照常
某个群上一个任务的结果无法确认时（例如回复是否送达不明，或执行器退出时没有结果），只暂停这个群，不重放、不重试，其他群继续处理。暂停的群收到新消息会回一句说明。
启动时不再被一个群拖住
某个群的记录恢复不了时，其他群照常启动，控制台把这个群标为「需要处理」。启动预检遇到这样的群会直接失败并列出原因。
新增封存命令
先重启服务；仍然暂停的群，在服务停止后运行 sintbot incident seal --group 群 ID。原记录原样封存，这个群换一份新记录重新开放，封存前未完成的消息不会再处理。
